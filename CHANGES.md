# Changes — 2026-10-06

Data model review of `CLAUDE.md`, then the first code for `packages/core`.

## `CLAUDE.md`

### `Video`
- `video_id` changed from `str` to `int`. It is now an internal surrogate key, assigned by the DB, and `None` until the video is stored. It moved to the end of the dataclass because it has a default.
- Added `native_id: str`, the platform's own ID for one video. `(platform, native_id)` is the natural key and is unique.
- Replaced `channel` with `channel_id` (stable platform ID) and `channel_name` (display name, may change).
- Added `ingested_at`: when we first recorded the video, as our own evidence alongside the platform-reported `posted_at`.
- `deleted_at` now defaults to `None`.
- Added a `key` property that returns `"{platform}:{native_id}"`, for logs.
- Made it `frozen=True, slots=True`.

### `Frame`
- `frame_id` changed from `str` to `int`. It is kept so the PDQ index can map hits to rows by integer.
- `frame_id` and `video_id` are now optional (`int | None = None`). They are `None` before storage, and `video_id` stays `None` for query clips.
- Field order changed: `offset` and `pdq` come first, since they have no defaults.
- Still a plain `@dataclass`, not frozen.

### `Match`
- `video_id` changed from `str` to `int`.
- `confidence` is intentionally left undefined for now.

### Notes under the data model
- Removed: "`(platform, post_id)` must be unique".
- Added:
  - `video_id` is internal, and `(platform, native_id)` is the unique natural key.
  - `native_id` formats: YouTube video ID; Telegram `{channel_id}/{message_id}` with the numeric channel ID; multi-video posts (X, Instagram) append `#{index}`.
  - Eval labels reference `(platform, native_id)`, never `video_id`.
  - All timestamps are tz-aware UTC.
  - Records are immutable; updates go through `dataclasses.replace`.

## New files

- `pyproject.toml`: uv workspace root, Python ≥ 3.11, with `packages/core` as its only member so far.
- `packages/core/pyproject.toml`: the `core` package, with no dependencies.
- `packages/core/src/core/models.py`: `Video`, `Frame`, `Match`, `QueryResult`, exactly as in `CLAUDE.md`.
- `packages/core/src/core/__init__.py`: re-exports the four classes.
- `packages/core/tests/test_models.py`: tests for `Video` defaults, `key`, immutability, and `Frame`'s `None` IDs.

## PDQ fingerprinting

### `CLAUDE.md`
- `Frame` gained `quality: int` (PDQ quality, 0–100), after `pdq`.
- `fingerprint_frame(image)` now returns `tuple[bytes, int]` (hash, quality) instead of `Frame`, since a single image has no offset.
- Added notes: PDQ comes from `pdqhash` (wraps Meta's C++ reference); Meta's quality cutoff of ≤ 49 is a starting threshold to tune on eval.

### Code
- `packages/core`: `Frame.quality` added; test updated.
- `packages/fingerprint/pyproject.toml`: new package; depends on `core`, `numpy`, `pdqhash`.
- `packages/fingerprint/src/fingerprint/pdq.py`: `fingerprint_frame` — validates an RGB uint8 image, returns the 32-byte hash (reference byte order) and quality.
- `packages/fingerprint/src/fingerprint/__init__.py`: exports `fingerprint_frame`.
- `packages/fingerprint/tests/test_pdq.py`: hash size and quality range, determinism, downscaled image stays within 31, different images exceed 31, flat image has quality ≤ 49, bad input rejected.
